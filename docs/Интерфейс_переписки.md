# Интерфейс переписки

Спецификация к этапам 2.7 и 3.3. Уточняет раздел 5.8 ТЗ — принятое решение отличается от исходного описания.

## Список слева: клиент, а не диалог

Левая колонка — список клиентов по ФИО, визуально как список чатов в Telegram: имя, последнее сообщение, время, счётчик непрочитанных.

**У клиента одна платформа.** Клик по строке открывает переписку. Платформа подписана в шапке чата — менеджер всегда видит, куда пишет.

**У клиента несколько платформ.** Клик по строке раскрывает её в подсписок: по строке на каждый канал, у каждого своё последнее сообщение и свой счётчик. Клик по подстроке открывает переписку конкретной платформы.

```
▸ Иванов Иван                    2 · 14:32     ← одна платформа, открывается сразу
▾ Петрова Мария                  5 · 14:28     ← раскрылась
    Telegram                     3 · 14:28
    WhatsApp                     2 · 11:04
```

## Чем это отличается от ТЗ

Раздел 5.8 описывает единую ленту, где сообщения со всех платформ идут вперемешку с пометкой у каждого, плюс переключатель платформы для ответа. Принято другое решение: **переписки по платформам не смешиваются**.

Причины:

1. **Совпадает с моделью данных.** `Dialog` — это пара «контакт × канал менеджера», уникальная по индексу. Клиент, писавший в Telegram и WhatsApp, физически имеет два диалога. Отдельные чаты показывают ровно то, что лежит в базе, без склейки.
2. **Нет проблемы сортировки.** `Message.CreatedAt` берётся с той стороны, часы платформ расходятся. При слиянии двух лент порядок сообщений местами получался бы неожиданным.
3. **Ответ уходит туда, откуда пришёл.** Переключатель платформы — источник ошибок: менеджер отвечает клиенту в канал, в котором тот, возможно, уже не читает. Здесь платформа определяется тем, какой чат открыт, и перепутать нечего.

## Что это меняет в остальном

**Пометка платформы у каждого сообщения не нужна** — весь чат принадлежит одной платформе, достаточно подписи в шапке.

**Переключатель платформы для ответа не нужен.**

**`Contact.PrimaryPlatform` остаётся**, но меняет смысл: это уже не «куда отвечать по умолчанию», а подсказка для интерфейса — какой подчат раскрывать первым и как сортировать свёрнутую строку.

**Счётчик непрочитанных на свёрнутой строке** — сумма по всем диалогам контакта. Сортировка списка — по максимальному `LastMessageAt` среди них.

## Следствие для этапа 2.7

Список слева строится **по контактам с самого начала**, хотя на втором этапе у каждого контакта будет ровно один диалог и разницы не видно. Иначе на третьем этапе придётся переписывать и список, и счётчики.

Само раскрытие в подсписок реализуется в 3.3, когда появится вторая платформа: раньше его нечем наполнить.
