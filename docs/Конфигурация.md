# Конфигурация MultiMessenger

Все внешние параметры читаются через `IConfiguration`. Хардкода хостов, портов и путей в коде нет — это условие из п. 1.3 плана, от которого зависит переезд в Docker на этапе 1.7.

## Источники настроек

Порядок применения (каждый следующий перекрывает предыдущий):

1. `appsettings.json` — структура и несекретные значения по умолчанию, коммитится.
2. `appsettings.Development.json` — настройки уровня логирования для локальной работы, коммитится.
3. **user-secrets** — локальные секреты разработчика, лежат вне репозитория (`%APPDATA%\Microsoft\UserSecrets\<UserSecretsId>`).
4. **Переменные окружения** — способ задания секретов на сервере.

Значения, зависящие от машины или являющиеся секретом, в `appsettings*.json` намеренно оставлены пустыми. Приложение не стартует, пока они не заданы, — это лучше, чем молча подключиться не туда.

## Параметры

| Ключ | Локально | На сервере | Секрет |
|---|---|---|---|
| `ConnectionStrings:Postgres` | user-secrets, `Host=localhost;Port=5433;...` | `ConnectionStrings__Postgres`, `Host=postgres;...` | да |
| `Minio:Endpoint` | user-secrets, `localhost:9000` | `Minio__Endpoint`, `minio:9000` | нет |
| `Minio:AccessKey` | user-secrets | `Minio__AccessKey` | да |
| `Minio:SecretKey` | user-secrets | `Minio__SecretKey` | да |
| `Minio:BucketName` | `appsettings.json`, `multimessenger-media` | то же | нет |
| `Minio:UseSsl` | `false` | `true` | нет |
| `Telegram:ApiId` | user-secrets | `Telegram__ApiId` | да |
| `Telegram:ApiHash` | user-secrets | `Telegram__ApiHash` | да |
| `Telegram:UseProxy` | `true`, если запуск из России | `false` на сервере в Германии | нет |
| `Telegram:MTProxyUrl` | user-secrets, `https://t.me/proxy?...` | не нужен при `UseProxy=false` | да |
| `Storage:SessionsBasePath` | `appsettings.json`, `./sessions` | `Storage__SessionsBasePath`, `/data/sessions` | нет |
| `Seq:ServerUrl` | user-secrets, `http://localhost:5341` | `Seq__ServerUrl` | нет |
| `Seq:ApiKey` | не нужен | `Seq__ApiKey`, если Seq защищён ключом | да |

Двойное подчёркивание в переменных окружения — стандартный разделитель уровней вложенности .NET, работает на всех платформах в отличие от двоеточия.

## Настройка рабочего места

Инфраструктура поднимается через `docker compose up -d`, значения берутся из `.env` (шаблон — `.env.example`).

Те же значения нужно продублировать в user-secrets, чтобы их увидело приложение:

```bash
dotnet user-secrets set "ConnectionStrings:Postgres" "Host=localhost;Port=5433;Database=multimessenger;Username=multimessenger;Password=<из .env>" --project src/MultiMessenger.Web
```

```bash
dotnet user-secrets set "Minio:Endpoint" "localhost:9000" --project src/MultiMessenger.Web
```

```bash
dotnet user-secrets set "Minio:AccessKey" "<MINIO_ROOT_USER из .env>" --project src/MultiMessenger.Web
```

```bash
dotnet user-secrets set "Minio:SecretKey" "<MINIO_ROOT_PASSWORD из .env>" --project src/MultiMessenger.Web
```

Посмотреть, что уже задано:

```bash
dotnet user-secrets list --project src/MultiMessenger.Web
```

## Валидация

Типизированные настройки живут в `src/MultiMessenger.Infrastructure/Configuration` и регистрируются одним вызовом `AddMultiMessengerOptions`.

- `MinioOptions` и `StorageOptions` проверяются **при старте** (`ValidateOnStart`) — без хранилища и путей к сессиям сервис бесполезен.
- Строка подключения проверяется там же, при регистрации, с подсказкой в тексте ошибки.
- `TelegramOptions` при старте **не** проверяются: на этапе 1 ключей ещё нет, и требовать их от каждого запуска незачем. Валидация сработает при первом обращении к `IOptions<TelegramOptions>`, то есть когда коннектор действительно создаётся. Там же проверяется связка `UseProxy`/`MTProxyUrl`: если прокси включён, адрес обязателен.

Настройка логирования — в [Логирование.md](Логирование.md).

`UserSecretsId` проекта хранится в `MultiMessenger.Web.csproj` и коммитится — это идентификатор хранилища, а не секрет.
